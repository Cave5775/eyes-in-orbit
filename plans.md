  - Code done: the scene prefers `earth-hires.jpg` (NASA Blue Marble, 8192 x 4096 from the 21600 x 10800 original, scaled down on smaller GPUs) and falls back to the 2k map. Closer than about 5,000 km a texel is magnified, so below about 2,600 km the DETAIL layer streams finer NASA GIBS tiles (down to 0.6 km per pixel) through the local server and blends them over the base map (`/api/imagery`, `data/imagery/` cache, DETAIL button). Checked in a headless browser only; between 2,600 and 5,000 km the base map is still slightly magnified

# Feature issues
- [x] Surface mode does not vertically fit an object, only tracks its surface position. When toggled without a focused object, locks to a specific point on Earth and cannot pan
  - Fixed, needs a manual look in the browser: the surface view now aims halfway up to the object and frames the whole ground-to-object segment (also on FIT of one object), and right/shift drag slides the ground target (a followed object is let go; with nothing focused the view roams)
- [x] Events timeline in Falcon 9 launch viewer stacks overlapping events so that the first event's text overlaps with the next event's line; change the stacking so that the first event is highest and subsequent ones are below it
  - Fixed (`labelY` in `lib/ascent-chart.ts`, unit-tested); needs a visual check on a real launch
- [x] Celestial bodies do not follow the logarithmic distance compression correctly
  - Fixed: `CelestialLayer` drew the Sun at its true 1.5e8 km and ignored the DISTANCE button. It now goes through `refDisplay` (`lib/ref-body.ts`, unit-tested): in COMPRESSED the Sun sits on the same log shell as probes (~2.9e6 km, same direction) and is scaled by the same factor, so it keeps its true angular size (the Moon is inside the 2e6 km threshold and is unchanged); TRUE SCALE is as before. The SUN tab follows the displayed position and frames/limits the camera by the displayed radius (`refViewDistKm`/`refMinDistKm` take the factor, `refMaxDistKm` only widens to 6e8 km in true scale), and switching the distance scale on the SUN tab re-frames it. Checked in headless Edge (EARTH/MOON/SUN tabs, both scales, switching on the Sun tab); not verified: the Sun as a disc in the sky from an Earth-centred camera, and the exact apparent size is a choice (same angular size as the real Sun)
- [x] Modeled trajectories only appear in the minutes leading up to launch
  - Fixed: `planPathWindow` gave composites the window now-5 min .. now+10 min, which before liftoff only holds the standing pad (no movement, nothing drawn). A composite made only of pad holds and sampled flight (launch vehicle ascent, booster return) now plans its whole flight (liftoff to end of the ascent or booster landing) whenever it is selected, days before or after; it is `anchored` so it is not rebuilt as the clock moves, and the HUD reads `PATH starts in 2d 23h, lasts 18m 30s` / `ended 3h 00m ago` (`fmtPathWindow`). Satellites, probes, the demo booster (has a relative landing arc), composites with an orbit segment and flights over 45 min keep the old window. Tests in `paths.test.ts`/`format.test.ts`; checked in headless Edge on the mock Crew-14 vehicle and booster at -3 d, -20 min, T+5 min, T+3 h. Not verified against real server data (Launch Library / Flight Club ascents) or on a real launch
