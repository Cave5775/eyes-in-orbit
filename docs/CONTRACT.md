# EyesInOrbit — build contract (server <-> web)

Reference feeds: `spaceflight_live_data_streams_reference.md`.
`packages/core` (`@eio/core`) is the shared spine: read `packages/core/src/{types,feeds,frames,bodies,entity-graph,mission-fsm,ascent}.ts` before coding. Units: km, km/s, ms since epoch. Frames: `EARTH:inertial` (TEME) / `EARTH:fixed`. Keep changes to `packages/core` additive.

Environment notes: Windows, Git Bash/PowerShell, Node 24, npm workspaces (no pnpm). `npm install` of git-based deps is blocked, so no `lightstreamer-client-node`. Write source files with the Write tool (big bash heredocs break). Run tests with `npx vitest run` from the repo root. Dev server port **8787**, web dev port **5173** with Vite proxy `/api` and `/stream` -> `http://localhost:8787`.

## HTTP API (server, Fastify, gzip via @fastify/compress, CORS open on localhost)

| Route | Returns |
|---|---|
| `GET /api/health` | `{ serverTime, entityCount, connectors: ConnectorHealth[] }` |
| `GET /api/entities?since=<ms>&kind=&body=&q=&group=&limit=` | `{ serverTime, entities: EntityRecord[] }` — full records including `provider` spec. No filters = whole catalog (~12k, rely on gzip). `since` = only records with `updatedAt > since`. |
| `GET /api/entities/:id` | `EntityRecord` (404 if unknown) |
| `GET /api/search?q=&limit=20` | lightweight `{id,name,kind,group,aliases}[]` ranked: exact id/NORAD/COSPAR alias > name prefix > substring |
| `GET /api/launches` | `{ launches: Launch[] }` sorted by NET, includes recent past (~10) + upcoming |
| `GET /api/news?entity=<id>&q=<text>&limit=20` | `{ articles: Article[] }`; without params = latest global news; with entity/q = SNAPI `search=` (entity query = `links.newsQuery` or name), cached 10 min |
| `GET /api/dsn` | `DsnSnapshot` |
| `GET /api/iss` | `{ fix?: IssFix, telemetry: TelemetryPoint[], arrays?: IssArrays }` (`arrays`: SARJ / BGA angles in degrees 0..360, attitude quaternion `[w,x,y,z]` body to LVLH, `verified` flags per part; see README "ISS array telemetry") |
| `GET /api/bodies` | `Body[]` from `@eio/core` registry (the raw registry, unchanged; the same bodies are also catalog entities, see "Bodies" under Entity conventions) |
| `GET /api/telemetry/:launchId` | `AscentSeries` (core `ascent-model.ts`): `{launchId, entityId, liftoffMs, source: 'modeled'\|'file'\|'live'\|null, modeled, file, live}`; `modeled` is the MODELED nominal Falcon 9 ascent (rows `{tSec,altKm,speedKmS,downrangeKm}`, events, phases), `live` the posted rows. 404 for an unknown launch id (`launch-<id>` also accepted) |
| `POST /api/telemetry/:launchId` | localhost only. Body `[{tSec,altKm,speedKmS}]` or `{rows, events?, azimuthDeg?, source?, replace?}`; 400 with a message on invalid rows. Replaces the launch entity's trajectory (`attrs.trajectorySource: 'live'`) and emits `entities.changed`. `DELETE` clears it. Format: see `apps/server/src/telemetry.ts` and README "Ascent telemetry" |
| `GET /api/imagery/:z/:x/:y.jpg` | A 512 px JPEG tile of NASA GIBS Blue Marble (shaded relief and bathymetry) for the web client's close-up Earth detail. Level `z` 3..6, `x` in 0..2^(z+1)-1, `y` in 0..2^z-1, tiles 180/2^z degrees square with row 0 at the north pole. Cached on disk under `data/imagery/`; 400 for a tile outside the grid, 404 when `OFFLINE=1` and the tile is not cached, 502 when NASA fails |
| `GET /api/credentials` | localhost only. `{credentials: CredentialInfo[]}` (`feeds.ts`): `{key, label, connector, secret, set, source: 'ui'\|'env'\|null, value?}`. `value` is present only for non-secret fields; secrets are never returned |
| `PUT /api/credentials` | localhost only. Body `{values: {spacetrackUser?, spacetrackPassword?, ll2Token?}}`, a string sets, `null` or `""` removes the UI value (falls back to the env var). All-or-nothing validation, 400 with a message on unknown keys, non-strings, control characters or more than 256 chars. Applies at once (connectors waiting for credentials start; Space-Track cache and retry gate reset on a changed login). Replies `{ok, changed, credentials}` |

## WebSocket `/stream` (JSON `ServerMessage` / `ClientMessage` from `feeds.ts`)
Server sends `hello` on connect, then pushes: `entities.changed` (client then refetches `/api/entities?since=`), `launches`, `news`, `dsn`, `health`, and `iss.fix` (1 Hz) / `iss.telemetry` / `iss.arrays` (about 1 Hz, `{type:'iss.arrays', arrays: IssArrays}`) **only while at least one client has subscribed to topic `iss`**. Client topics: `iss` (others always pushed). Server pings; client auto-reconnects with backoff.

## Entity conventions (server produces, web consumes)
- Satellites: id `sat-<NORAD>`, `provider: {type:'sgp4', omm}`, `aliases: {norad, cospar}`, `group` in `stations|active|starlink|cosmos-2251-debris|iridium-33-debris|fengyun-1c-debris|gps-ops|glo-ops|galileo|beidou|amateur` (the four GNSS groups are the navigation constellations and get `render.colorKey: 'navigation'`, `amateur` keeps the `satellite` colour; dedupe priority stations, starlink, debris clouds, navigation, amateur, active; the debris groups force kind `debris`; the web client groups objects by the launch id `YYYY-NNN` taken from `aliases.cospar`), kind `station` (ISS, Tiangong/CSS/Tianhe), `debris` (name contains DEB/R/B and ' DEB'), else `satellite`; `render.colorKey` = `station|starlink|navigation|satellite|debris` (advisory: the web client colours an object by its category, `categoryOf` in `apps/web/src/lib/browser-ui.ts`, so `starlink` is drawn like `satellite`); ISS also gets `render.footprint: true, orbitLine: true, trailSeconds: 5400, model: 'iss'` (`render.model` is a key of the web client's 3D model registry: `iss`, `satellite`, `rocket-stage`; launch boosters use `rocket-stage`) and `links.streams` (NASA ISS HD Earth viewing / NASA TV YouTube embeds as `kind:'youtube'`—use known stable URLs like `https://www.youtube.com/watch?v=...` only if verified, otherwise `kind:'nasa-tv'` with `https://www.nasa.gov/nasalive`).
- Bodies: the registry bodies are also entities, produced by the offline `bodies` connector from `bodyEntityRecords()` (core `hierarchy.ts`; the web mock and the web fallback `withBodyEntities` use the same function). Ids `body-<registry id lowercase>` (`body-sun`, `body-earth`, `body-mars`, `body-moon`), kind `star` (no parent), `planet` (parent is a star) or `moon` (parent is a planet), `group: 'bodies'`, `provider: {type:'body', bodyId}` (state in `EARTH:inertial` from `bodyStateEci`, always valid; `bodyId` inside the provider is the registry id of the body itself). The entity's own `bodyId` is its PRIMARY (the registry id of the body it orbits; the Sun's own id for the Sun) and `parentId` is the primary's entity id (`body-earth` for the Moon, `body-sun` for the planets; absent for the Sun), so the hierarchy reads Sun, planets, moons, then objects orbiting them. `aliases: {body: <registry id>, alt?: <other name>}` (e.g. Moon: `alt` Luna), both searched by `/api/search` and `q=`. `render: {orbitLine: true (not the Sun), label: true, colorKey: 'body'}`, `attrs: {radiusKm, gm, periodDays?, approx}`. A body entity is found by `?kind=moon|planet|star`, `?group=bodies` and `/api/search?q=moon`. `GET /api/bodies` still returns the raw `Body[]` registry (frame maths, radii) and is not derived from the entities. A client that finds no body entity in the catalog (connector disabled via `DISABLED_CONNECTORS=bodies`, older server) adds them itself. The web app addresses a body only by its entity id (selection, the frame of reference, the tree, the breadcrumb): `bodyOf(rec)` (core `hierarchy.ts`) is the one converter to the registry id and `isOrbitable(rec)` (a body entity, or `attrs.orbitable === true`) says whether an entity can be the frame.
- `createdAt` (optional, additive): the hub sets it on the first insert of an entity id and never changes it, while `updatedAt` moves with every change. Absent on records from older servers and on mock entities (sort by `createdAt ?? updatedAt`).
- Booster: recovered Falcon 9 first stages (modeled ascent only) also get `launch-<ll2 id>-booster`, kind `stage`, `parentId` the launch entity, a `composite` of pad, ascent to separation, the modeled return and a `geodetic` landed segment (`attrs.trajectorySource: 'modeled'`, `recovery`, `landingDownrangeKm`); `AscentSeries.modeled.booster` carries its rows.
- Payload: launches that are flying or flown (`phase` ACTIVE_ASCENT, ORBIT_INSERTION or ON_ORBIT, not failed) whose ascent reaches orbit also get `launch-<ll2 id>-payload`, kind `satellite`, `parentId` the launch entity, `group: 'launches'`, `render: {colorKey: 'satellite', label: true, orbitLine: true}`, a `composite` of one `keplerian` segment (`bodyId: 'EARTH'`, phase `on orbit (modeled)`) that starts at the end of the modeled ascent (T+1110 s for Falcon 9) and ends about 12 h later (no pad tail, so no position outside that window), `attrs.trajectorySource: 'modeled'`. It is a PLACEHOLDER until the payload appears in a TLE feed: two-body, no J2, no drag. The launch vehicle's own `composite` ends the same way (`on orbit (modeled)`, then the `pad (launch complete)` marker); launches with status failure or partial failure skip the orbit and return to the pad marker right after the ascent. A trajectory file that ends on an orbit gets the same continuation, one that ends before it holds its last fix (`last fix (held)`).
- Launches: id `launch-<ll2 id>`, kind `launch_vehicle`, `phase` from `deriveMissionState`, provider = `geodetic` at the pad, or `composite` (pad before NET, `sampled` ascent in `EARTH:fixed` after) from posted telemetry, a trajectory file in `data/trajectories/`, or the modeled nominal ascent for Falcon 9 launches (`attrs.trajectorySource: 'live'|'file'|'modeled'`; modeled/live launches also carry `events`: LIFTOFF, MAX_Q, MECO, STAGE_SEP, SES, FAIRING_SEP, SECO and the booster ENTRY_BURN, LANDING_BURN, LANDING), `links: {streams, newsQuery, launchId}`, attrs (provider, vehicle, orbit, pad, status). Re-derive phase every 15 s (emit `entities.changed` only when phase changes).
- DSN: ground station entities `dsn-goldstone|madrid|canberra` (kind `ground_station`, geodetic: Goldstone 35.4267,-116.8900; Madrid 40.4314,-4.2481; Canberra -35.4014,148.9817); spacecraft entities `dsn-<CODE>` (kind `probe`, `aliases.dsn=CODE`, positions from JPL Horizons vectors: by default geocentric, sampled provider in `EARTH:inertial`, `bodyId` `EARTH`, 30-min step over [fetch hour -3 d, +7 d], refreshed every 12 h, cached in SQLite for 23 h. Each target may override centre, frame, `bodyId`, step and window in `dsn-targets.ts` (`HorizonsSpec`); LRO is fetched Moon-centred: `CENTER 500@301`, sampled provider in `MOON:inertial`, `bodyId` `MOON`, 5-min step over [-1 d, +3 d] (1153 rows, with velocities for Hermite interpolation), `attrs.trackCentre='Moon'`. The Mars orbiters MRO, ODY, TGO (5-min step) and MVN, MEX (10-min step) are fetched the same way Mars-centred: `CENTER 500@499`, sampled provider in `MARS:inertial`, `bodyId` `MARS`, [-1 d, +3 d] (1153 / 577 rows), `attrs.trackCentre='Mars'`; landers and rovers (MSL, M20) and cruising probes stay geocentric. The cache key includes target, centre, step and window. Vectors are ICRF J2000 while the core frames are equatorial of date (about 0.36 deg of precession in 2026, ~11 km at lunar distance), accepted; table of Horizons ids: VGR1 -31, VGR2 -32, JWST -170, M20 -168, MSL -76, MRO -74, ODY -53, MVN -202, NHPC -98, JNO -61, LRO -85, PSP -96, TGO -143, MEX -41, LUCY -49, PSYC -255, EURC -159, SOLO -144, BEPI -121, STA, SOHO, TESS, CHDR; full list in `apps/server/src/connectors/dsn-targets.ts`). Link DSN activity to entities via `attrs` (rangeKm, rtltSec, dataRate, dish).

## Web architecture
Vite + React 18 + zustand + three.js (r170) raw `SceneController` (not r3f). `satellite.js` v6 propagation in a Web Worker writing a transferable `Float32Array` of ECI positions (km) at ~30 Hz for every `sgp4` entity; other providers via `EntityGraph` on the main thread. Render in Earth-inertial; rotate the Earth mesh by `gmstRad`, sun light from `sunDirectionEci`. Everything is drawn to scale at its true position, float64 camera-relative (the Sun at 1.5e8 km, Voyager 1 at 2.5e10 km; logarithmic depth buffer, far plane 1e13 km; zoom-out limit 1e11 km); there is no distance compression. Live stream iframe lives in a `React.memo` panel keyed only by URL. Offline-capable: procedural Earth when `public/textures/earth-hires.jpg` (8192 px, `npm run assets`) is missing; there is no lower-resolution fallback map.
