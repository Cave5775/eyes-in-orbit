# EyesInOrbit: data-worker contract

The page and the browser data engine talk over one message port. The engine (`apps/web/src/engine`, wired by `apps/web/src/workers/data.service.ts`, run as a dedicated worker by `data.worker.ts`) owns every upstream call, the IndexedDB cache, the entity catalogue and the schedulers; the page (`apps/web/src/api/worker-api.ts`, `worker-stream.ts`) only asks and listens. There is no HTTP API and no WebSocket: the host serves static files plus the stateless `/relay` handler (see docs/reference.md, "Deployment"). Source of truth for the types: `apps/web/src/workers/data.protocol.ts`, `apps/web/src/api/types.ts` (`Api`) and `packages/core/src/feeds.ts`.

`packages/core` (`@eio/core`) is the shared spine: read `packages/core/src/{types,feeds,frames,bodies,entity-graph,mission-fsm,ascent}.ts` before coding. Units: km, km/s, ms since epoch. Frames: `EARTH:inertial` (TEME) / `EARTH:fixed`. Keep changes to `packages/core` additive.

Environment notes: Windows, Git Bash/PowerShell, Node 24, npm workspaces (no pnpm). Run tests with `npx vitest run` from the repo root.

## Messages

Page to worker (`ToWorker`):

| Message | Meaning |
|---|---|
| `{ kind: 'rpc', id, method, args }` | Call one `Api` method (list below). The worker answers with exactly one `result` carrying the same `id`. |
| `{ kind: 'start' }` | A stream consumer is there. The worker pushes `hello`, `health`, `launches` (if any), `news` (if any), `dsn` (if any links) and `minorPlanets`, then every later event. Events before `start` are dropped. |
| `{ kind: 'stop' }` | The consumer is gone: pushing stops and all its topics are released. |
| `{ kind: 'client', msg }` | `ClientMessage`: `{ op: 'subscribe' \| 'unsubscribe', topics: string[] }`. |

Worker to page (`FromWorker`):

| Message | Meaning |
|---|---|
| `{ kind: 'ready' }` | The worker script is up (the engine starts asynchronously; messages sent earlier wait until it has started). |
| `{ kind: 'fatal', error }` | The engine could not start at all. Every later `rpc` fails with "the data engine did not start"; the page falls back to the mock. |
| `{ kind: 'event', msg }` | A pushed `WorkerEvent`: the core `ServerMessage`s or `{ type: 'minorPlanets', status }`. |
| `{ kind: 'result', id, ok: true, value }` | The answer to an `rpc`. `minorPlanetChunk` hands its bytes over (transferred, not copied). |
| `{ kind: 'result', id, ok: false, error }` | The failure of an `rpc`, an `RpcError`. |

## RPC methods

`RPC_METHODS` is the whole list; the handler rejects any other name (`unknown method <name>`). `mapTile` is an `Api` method that is not an RPC: it only builds a NASA URL in the page. There is deliberately no method that writes or clears telemetry rows: nothing outside the engine may change what the app draws for a launch.

| Method | Arguments | Result |
|---|---|---|
| `entities` | `since?: number, page?: { offset?, limit? }` | `{ serverTime, entities: EntityRecord[], next?, total? }`: everything, or what changed after `since` (`updatedAt > since`). With `limit` or `offset`, one page; `next` is present unless it is the last page (the web client pages every catalogue load). |
| `search` | `q: string, limit?: number` | `SearchHit[]` (`id, name, kind, group, aliases`), ranked: exact id or alias, name prefix, substring. `limit` defaults to 20, capped at 100. |
| `match` | `q: string` | `{ q, ids, total, truncated, via }`: every entity whose id, name or an alias contains `q` (case-insensitive), best first by the one ranking of `matchScore` (`@eio/core` match.ts: exact id or alias, name prefix, word prefix, substring; equal scores by name, then id). `truncated` means the cap cut the list (rank locally instead); `via` is `scan` (the engine ranks its catalogue directly) or `index`. |
| `launches` | none | `Launch[]`, sorted by NET, recent past (about 10) and upcoming. |
| `news` | `{ entity?, q?, limit? }` | `Article[]`. Without `entity` and `q`: the latest global news. With either: a Spaceflight News `search=` query (an entity's query is `links.newsQuery` or its name; the text is lower-cased, whitespace-collapsed and cut at 80 characters), cached 10 min, 20 searches per hour. `limit` defaults to 20, capped at 50. An unknown entity is an error. |
| `dsn` | none | `DsnSnapshot`. |
| `describe` | `entityId` | `Description` (`describe.ts` in core): `{entityId, norad?, summary?, wikidata?, discos?, fallback, searchUrl, sources: {wikidata, wikipedia, discos each ok, miss, off, error or limited}, fetchedAt, fromCache?, limitedUntil?}`. Looked up on demand (Wikidata, Wikipedia, ESA DISCOS with a token) and cached in the browser. `limited` means the request limiter refused the call. An unknown entity is an error. |
| `archiveImages` | `observatoryId, bodyId` | `ArchiveImagesResult` (`archive-images.ts` in core): `{observatoryId, observatory, body, archive: {id, label, url} \| null, status: 'ok' \| 'none' \| 'unsupported' \| 'error', reason?, images: ArchiveImage[], total?, fetchedAt, fromCache?, limitedUntil?}`. Hubble and JWST through MAST, cached 6 h per body. `bodyId` must be a registry id such as `JUPITER`. |
| `iss` | none | `{ fix?: IssFix, telemetry: TelemetryPoint[], arrays?: IssArrays }` (`arrays`: SARJ and BGA angles in degrees 0..360, attitude quaternion `[w,x,y,z]` body to LVLH, `verified` flags per part; see docs/reference.md, "ISS array telemetry"). |
| `health` | none | `{ serverTime, entityCount, connectors: ConnectorHealth[], storage?: StorageInfo }`; `storage` is `{ persistent, persisted?, usageBytes?, quotaBytes?, error? }` (`persistent: false`: IndexedDB could not be opened, so everything lives in memory). |
| `ascent` | `launchId` | `AscentSeries` (core `ascent-model.ts`): `{launchId, entityId, liftoffMs, source: 'modeled' \| 'file' \| 'live' \| null, modeled, file, live}`, or `null` for an unknown launch id. `modeled` is the MODELED nominal Falcon 9 ascent (rows `{tSec,altKm,speedKmS,downrangeKm}`, events, phases). |
| `traverse` | `entityId` | `RoverTraverse` (core `surface-sites.ts`) of `dsn-MSL` or `dsn-M20`, read from the store, never from the network: `{entityId, bodyId: 'MARS', source, fetchedAt, stale, points: [[latDeg, lonDeg, sol], ...]}`, every localization of the NASA MMGIS waypoint layer in drive order, consecutive repeats removed, planetocentric degrees east. `null` when unknown or not stored yet. |
| `minorPlanetIndex` | none | `MinorPlanetIndex` of the stored MPCORB orbits (about 1.4 million, packed sorted by H, brightest first): `{count, chunkSize: 65536, chunks, fetchedAt, stale, skipped, epochMin, epochMax, credit}`, or `null` when nothing is stored. |
| `minorPlanetChunk` | `k` | The bytes of chunk `k` as an `MPCB` container (core `mpcorb.ts`), transferred. An unstored chunk is an error. |
| `minorPlanetsStatus` | none | `MinorPlanetStatus`: `{ state: 'none' \| 'downloading' \| 'ready' \| 'failed', phase?: 'checking' \| 'downloading' \| 'storing', count?, fetchedAt?, error? }`. Changes are also pushed as `minorPlanets` events. |
| `minorPlanetsDownload` | `{ force? }` | Starts (or joins) the opt-in download of MPCORB (about 70 MB); fresh stored data is left alone unless `force`. Resolves with the final status. |
| `minorPlanetsCancel` | none | Aborts a download in progress; stored data is kept. |
| `credentials` | none | `CredentialInfo[]` (`feeds.ts`): `{key, label, connector, secret, set, source, value?}`. `value` is present only for non-secret fields; secrets are reported as set or not set only. |
| `saveCredentials` | `{ spacetrackUser?, spacetrackPassword?, ll2Token?, discosToken? }` | A string sets a value, `null` removes it. Stored unencrypted in this browser profile (IndexedDB). Applies at once: connectors that wait for credentials run again. Resolves with the new `CredentialInfo[]`. |
| `clearCredentials` | none | Removes every saved credential. Resolves with the new `CredentialInfo[]`. |

## Events and topics

`WorkerEvent` is `ServerMessage` (`feeds.ts`) or `{ type: 'minorPlanets'; status: MinorPlanetStatus }`:

| Event | When |
|---|---|
| `hello` `{ serverTime, entityCount }` | Answer to `start`. |
| `entities.changed` `{ ids, at }` | The catalogue changed; the client then calls `entities(since)`. |
| `launches`, `news`, `dsn` | A feed produced a new list or snapshot. |
| `health` `{ connectors }` | Feed health changed; a burst is one message (throttled to `HEALTH_THROTTLE_MS`, 2 s). |
| `iss.fix` (every 2 s), `iss.telemetry`, `iss.arrays` (about 1 Hz) | Only while the page has subscribed to topic `iss`; subscribing also replays the current values. |
| `minorPlanets` `{ status }` | The opt-in minor-planet download changed state. |

Topics: only `iss` is a real topic; everything else is always pushed after `start`. A client sends `{ op: 'subscribe' | 'unsubscribe', topics }`; a topic name is a string of at most 64 characters, at most `MAX_TOPICS` (16) are held, and subscribing makes the hub run the connector that needs a subscriber (the ISS live feed runs only while `iss` is subscribed).

## Errors

An `rpc` that fails answers `{ ok: false, error: RpcError }`, `RpcError = { message, name?, retryAt?, limited? }`. A request the engine's limiter refused carries `limited: true` and `retryAt` (ms since epoch when asking is possible again); the message reads `rate limited until HH:MMZ (reason)`. Other failures carry the error message (`unknown entity <id>`, `unknown method <name>`, validation messages, upstream `HTTP <status> for <url>` texts).

**Health payload.** Each `ConnectorHealth` (the `health` RPC and the `health` event) keeps its raw fields (`status` idle|ok|error|disabled|stub, `lastOkAt`, `lastError`, `nextRunAt`, `runs`, `note`, `fromCache`) plus `failures` (consecutive failed runs), `offline` (offline mode, `VITE_OFFLINE=1`, and the connector needs the network), `limit` (the request budget from the engine's limiter, below) and `feed`, computed by the engine with `classifyFeed` (`packages/core/src/feed-state.ts`):

```ts
feed: {
  level: 'ok' | 'orange' | 'red' | 'off', // green | degraded, data or a temporary cause | nothing usable | disabled/offline/stub/not run
  reason: FeedReason,  // ok idle disabled offline stub no-credentials partial backoff rate-limited timeout server-error no-ephemeris stale blocked unreachable auth invalid repeated error
  note?: string,       // the last error (or the connector note when ok)
  retryUtc?: string,   // 'HH:MMZ' when the message says the feed is waiting for a retry time
  hasData: boolean,    // an earlier run delivered data the app still holds
}
```

Orange = degraded but data is still there or the cause is temporary (backoff while serving cache/file data, partial results, HTTP 429, stale-cache fallback, a timeout or 5xx for a feed that has delivered, no ephemeris for one target). Red = nothing usable (HTTP 403 / connect timeout / reset / unreadable response with no data, HTTP 401 or a failed login, 3 failed runs in a row with no data). Clients should use `feed` and may fall back to `classifyFeed(h)` for a record without it.

`limit?: { used, cap, window: 'minute'|'hour'|'day', nextAllowedAt?, blockedUntil?, blockKind?: 'rate'|'failure' }` is the request budget of the feed's source from `apps/web/src/engine/net/limiter.ts` (the busiest window, used of cap; `nextAllowedAt` while the minimum spacing holds; `blockedUntil` while the source is blocked after 403/429/503, Retry-After, repeated failures or a failed login). A `rate` block in force (403/429/Retry-After/X-Rate-Limit, caps) makes `feed` orange with reason `rate-limited`; a `failure` block (our own backoff after failures) keeps the normal failure mapping, including red `repeated` and `retryUtc` (a rejected login stays red `auth`); a run the limiter refused carries the message `rate limited until HH:MMZ (reason)`. Absent for feeds without caps. See `docs/reference.md`, "Rate limits".

## Entity conventions (the engine produces, the page consumes)
- Satellites: id `sat-<NORAD>`, `provider: {type:'sgp4', omm}`, `aliases: {norad, cospar}`, `group` in `stations|active|starlink|cosmos-2251-debris|iridium-33-debris|fengyun-1c-debris|gps-ops|glo-ops|galileo|beidou|amateur` (the four GNSS groups are the navigation constellations and get `render.colorKey: 'navigation'`, `amateur` keeps the `satellite` colour; dedupe priority stations, starlink, debris clouds, navigation, amateur, active; the debris groups force kind `debris`; the web client groups objects by the launch id `YYYY-NNN` taken from `aliases.cospar`), kind `station` (ISS, Tiangong/CSS/Tianhe), `debris` (name contains DEB/R/B and ' DEB'), else `satellite`; `render.colorKey` = `station|starlink|navigation|satellite|debris` (advisory: the web client colours an object by its category, `categoryOf` in `apps/web/src/lib/browser-ui.ts`, so `starlink` is drawn like `satellite`); ISS also gets `render.footprint: true, orbitLine: true, trailSeconds: 5400, model: 'iss'` (`render.model` is a key of the web client's 3D model registry: `iss`, `satellite`, `rocket-stage`; launch boosters use `rocket-stage`) and `links.streams` (NASA ISS HD Earth viewing / NASA TV YouTube embeds as `kind:'youtube'`—use known stable URLs like `https://www.youtube.com/watch?v=...` only if verified, otherwise `kind:'nasa-tv'` with `https://www.nasa.gov/nasalive`).
- Bodies: the registry bodies are also entities, produced by the offline `bodies` connector (`apps/web/src/engine/connectors/bodies.ts`) from `bodyEntityRecords()` (core `hierarchy.ts`; the web mock and the web fallback `withBodyEntities` use the same function). Ids `body-<registry id lowercase>` (`body-sun`, `body-earth`, `body-mars`, `body-moon`, and the rest of the solar system: `body-mercury`, `body-venus`, `body-jupiter`, `body-saturn`, `body-uranus`, `body-neptune`, the dwarf planets `body-ceres`, `body-pluto`, `body-eris`, `body-haumea`, `body-makemake`, the moons `body-phobos`, `body-deimos`, `body-io`, `body-europa`, `body-ganymede`, `body-callisto`, `body-mimas`, `body-enceladus`, `body-tethys`, `body-dione`, `body-rhea`, `body-titan`, `body-iapetus`, `body-miranda`, `body-ariel`, `body-umbriel`, `body-titania`, `body-oberon`, `body-triton`, `body-charon`, and the smaller moons `body-amalthea`, `body-thebe`, `body-himalia`, `body-hyperion`, `body-phoebe`, `body-janus`, `body-epimetheus`, `body-puck`, `body-nereid`, `body-despina`, `body-galatea`, `body-larissa`, `body-proteus`, `body-nix`, `body-hydra`, the asteroids `body-vesta`, `body-pallas`, `body-hygiea`, `body-psyche`, `body-bennu`, `body-ryugu`, `body-didymos`, `body-apophis`, `body-eros`, `body-itokawa`, `body-arrokoth` and Didymos's moon `body-dimorphos`; 62 in all, the new ones appended to the registry so existing ranks do not move; Nereid and Puck have no `attrs.gm`: GM not determined, the registry holds 0), kind `star` (no parent), `planet` (parent is a star), `dwarf_planet` (parent is a star, `Body.dwarf`), `asteroid` (parent is a star, `Body.asteroid`) or `moon` (parent is a planet or dwarf planet), `group: 'bodies'`, `provider: {type:'body', bodyId}` (state in `EARTH:inertial` from `bodyStateEci`, always valid; `bodyId` inside the provider is the registry id of the body itself; the optional `ephemeris: {frame, samples}` is the real data stream of the `horizons-bodies` connector: `[tMs,x,y,z,vx,vy,vz]` rows (km, km/s) relative to the parent in `<PARENT>:inertial`, ICRF axes, which `BodyProvider` installs in the registry so it replaces the approximate Kepler orbit inside the sampled window; the record's id, kind, parent and rank do not change, and without the stream (offline, mock, a failed target) the body is analytic). The entity's own `bodyId` is its PRIMARY (the registry id of the body it orbits; the Sun's own id for the Sun) and `parentId` is the primary's entity id (`body-earth` for the Moon, `body-sun` for the planets; absent for the Sun), so the hierarchy reads Sun, planets, moons, then objects orbiting them. `aliases: {body: <registry id>, alt?: <other name>}` (e.g. Moon: `alt` Luna), both searched by `search` and `match`. `render: {orbitLine: true (not the Sun), label: true, colorKey: 'body'}`, `attrs: {radiusKm, gm, periodDays?, approx}`. The raw `Body[]` registry (frame maths, radii) stays in `@eio/core` and is not derived from the entities. A client that finds no body entity in the catalog (connector disabled, mock) adds them itself. The web app addresses a body only by its entity id (selection, the frame of reference, the tree, the breadcrumb): `bodyOf(rec)` (core `hierarchy.ts`) is the one converter to the registry id and `isOrbitable(rec)` (a body entity, or `attrs.orbitable === true`) says whether an entity can be the frame.
- `createdAt` (optional, additive): the hub sets it on the first insert of an entity id and never changes it, while `updatedAt` moves with every change. Absent on mock entities (sort by `createdAt ?? updatedAt`).
- Booster: recovered Falcon 9 first stages (modeled ascent only) also get `launch-<ll2 id>-booster`, kind `stage`, `parentId` the launch entity, a `composite` of pad, ascent to separation, the modeled return and a `geodetic` landed segment (`attrs.trajectorySource: 'modeled'`, `recovery`, `landingDownrangeKm`); `AscentSeries.modeled.booster` carries its rows.
- Payload: launches that are flying or flown (`phase` ACTIVE_ASCENT, ORBIT_INSERTION or ON_ORBIT, not failed) whose ascent reaches orbit also get `launch-<ll2 id>-payload`, kind `satellite`, `parentId` the launch entity, `group: 'launches'`, `render: {colorKey: 'satellite', label: true, orbitLine: true}`, a `composite` of one `keplerian` segment (`bodyId: 'EARTH'`, phase `on orbit (modeled)`) that starts at the end of the modeled ascent (T+1110 s for Falcon 9) and ends about 12 h later (no pad tail, so no position outside that window), `attrs.trajectorySource: 'modeled'`. It is a PLACEHOLDER until the payload appears in a TLE feed: two-body, no J2, no drag. The launch vehicle's own `composite` ends the same way (`on orbit (modeled)`, then the `pad (launch complete)` marker); launches with status failure or partial failure skip the orbit and return to the pad marker right after the ascent. A trajectory file that ends on an orbit gets the same continuation, one that ends before it holds its last fix (`last fix (held)`).
- Launches: id `launch-<ll2 id>`, kind `launch_vehicle`, `phase` from `deriveMissionState`, provider = `geodetic` at the pad, or `composite` (pad before NET, `sampled` ascent in `EARTH:fixed` after) from a trajectory file in `data/trajectories/` (bundled into the build), or the modeled nominal ascent for Falcon 9 launches (`attrs.trajectorySource: 'file'|'modeled'` (`'live'` is only produced by the engine's telemetry service, which has no ingest route); modeled launches also carry `events`: LIFTOFF, MAX_Q, MECO, STAGE_SEP, SES, FAIRING_SEP, SECO and the booster ENTRY_BURN, LANDING_BURN, LANDING), `links: {streams, newsQuery, launchId}`, attrs (provider, vehicle, orbit, pad, status). Re-derive phase every 15 s (emit `entities.changed` only when phase changes).
- Surface sites: landers, rovers and the Ingenuity helicopter on the Moon, Mars and Titan (core `SURFACE_SITES`, one cited table; the `surface-sites` connector and the mock build them with `surfaceSiteRecords()`): ids `site-<name>` (`site-apollo-11`, `site-viking-1`, `site-ingenuity`), kind `lander`, `rover` or `drone` (the helicopter), `bodyId` the body they stand on (`MOON`, `MARS`, `TITAN`), group `surface`, `provider: {type:'geodetic', bodyId, latDeg, lonDeg, altKm: 0}` (planetocentric latitude, east longitude, on the body's sphere; see docs/frames.md, Surface sites), `render.colorKey` `rover`, `aircraft` or `probe`, `attrs` with `status` (`active`|`inactive`), `landedYear`, `agency`, `latDeg`, `lonEastDeg`, `elevationM` where known and `coordinateSource` (the citation). The two active Mars rovers keep the DSN ids `dsn-MSL` and `dsn-M20` (kind `rover`, group `dsn`, `aliases.dsn` and `aliases.horizons`): the same entity, not a DSN probe plus a rover; they are not Horizons targets, their position is the latest waypoint of the NASA MMGIS layer (`attrs.waypointSol`, `waypointSite`, `waypointDrive`, `driveTotalKm`, `positionFetchedAt`). The same MMGIS answer is stored once in the engine store (`surface-sites:v2:<M20|MSL>`: the latest waypoint and the whole traverse, no parallel file); the `traverse` RPC returns its points and the scene draws them on Mars when the rover is selected.
- DSN: ground station entities `dsn-goldstone|madrid|canberra` (kind `ground_station`, geodetic: Goldstone 35.4267,-116.8900; Madrid 40.4314,-4.2481; Canberra -35.4014,148.9817); spacecraft entities `dsn-<CODE>` (kind `probe`, `aliases.dsn=CODE`; the stored kind stays `probe` for every target, the web client shows an orbiter of another body (MRO, LRO...) as a satellite, derived from its track: `typeOf`, `apps/web/src/lib/view-class.ts`; positions from JPL Horizons vectors: by default geocentric, sampled provider in `EARTH:inertial`, `bodyId` `EARTH`, 30-min step over [fetch hour -3 d, +7 d], refreshed every 12 h, cached in the engine store for 23 h. Each target may override centre, frame, `bodyId`, step and window in `dsn-targets.ts` (`HorizonsSpec`); LRO is fetched Moon-centred: `CENTER 500@301`, sampled provider in `MOON:inertial`, `bodyId` `MOON`, 5-min step over [-1 d, +3 d] (1153 rows, with velocities for Hermite interpolation), `attrs.trackCentre='Moon'`. The Mars orbiters MRO, ODY, TGO (5-min step) and MEX (10-min step) are fetched the same way Mars-centred: `CENTER 500@499`, sampled provider in `MARS:inertial`, `bodyId` `MARS`, [-1 d, +3 d] (1153 / 577 rows), `attrs.trackCentre='Mars'`; cruising probes stay geocentric (the Mars rovers MSL and M20 are no Horizons targets any more: surface sites, see the Surface sites entry above). The cache key includes target, centre, step and window. Vectors are ICRF J2000 while the Earth and Moon frames are equatorial of date (0.0066 rad of precession in 2026): the connector precesses the samples of an `EARTH:inertial` or `MOON:inertial` stream (position and velocity) into the axes of date at ingest (core `streamToFrameAxes`), so `samples` of a `sampled` provider are always in the axes of its `frame` (no wire change; J2000 frames such as `MARS:inertial` are untouched); table of Horizons ids: VGR1 -31, VGR2 -32, JWST -170, MRO -74, ODY -53, NHPC -98, JNO -61, LRO -85, PSP -96, TGO -143, MEX -41, LUCY -49, PSYC -255, EURC -159, SOLO -144, BEPI -121, STA, SOHO, TESS, CHDR, EUCL -680; full list in `apps/web/src/engine/connectors/dsn-targets.ts`; a target with `ended: 'YYYY-MM-DD'` gets no request and no entity: MAVEN, -202, declared over 2026-06-03 per science.nasa.gov/mission/maven). Observatories: any entity may carry `attrs.observatory` (`'ground'|'space'`), `attrs.observatoryBands` (comma separated words) and `attrs.observatorySurvey` (the HiPS survey ids of its own instruments, comma separated, the first is the default; empty when there is no sky imagery; a single id, the older form, still reads); core `observatoryOf()` returns `ObservatoryMeta { site, bands, surveys: string[] }`. Set on JWST, TESS, Chandra, Euclid (`dsn-JWST|TESS|CHDR|EUCL`, Euclid is Horizons -680), Hubble, XMM-Newton and Fermi (`sat-20580|25989|33053`, `group` stays the CelesTrak group), the three DSN complexes (radio, no survey) and on the ground sites `obs-maunakea|paranal|rubin|haleakala|apachepoint|vla|kittpeak|ctio|sidingspring|palomar` (kind `ground_station`, `group: 'observatory'`, geodetic, produced by the offline `observatories` connector from core `GROUND_OBSERVATORIES`); there is no new EntityKind. Link DSN activity to entities via `attrs` (rangeKm, rtltSec, dataRate, dish).

## Web architecture
Vite + React 18 + zustand + three.js (r170) raw `SceneController` (not r3f). `satellite.js` v6 propagation in a Web Worker writing a transferable `Float32Array` of ECI positions (km) at ~30 Hz for every `sgp4` entity; other providers via `EntityGraph` on the main thread. Render in Earth-inertial; rotate the Earth mesh by `gmstRad`, sun light from `sunDirectionEci`. Everything is drawn to scale at its true position, float64 camera-relative (the Sun at 1.5e8 km, Voyager 1 at 2.5e10 km; logarithmic depth buffer, far plane 1e13 km; zoom-out limit 1e11 km); there is no distance compression. Live stream iframe lives in a `React.memo` panel keyed only by URL. Offline-capable: procedural Earth when `public/textures/earth-hires.jpg` (8192 px, `npm run assets`) is missing; there is no lower-resolution fallback map.
